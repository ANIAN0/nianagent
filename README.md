# Moon

本地 agent 应用，使用 React、Vite、shadcn/ui 和 Tauri。工作区、模型与会话配置保存于本机；对话和工具执行由 Pi SDK 提供。

## 运行

开发使用 Node.js 24.16.0、pnpm 11.24.0，以及 Rust 和 Tauri 的平台依赖。Windows 发行包自带 Node 运行时，使用者无需另行安装 Node。

```powershell
pnpm install --frozen-lockfile
pnpm tauri dev
```

`pnpm tauri dev` 同时启动开发页面和本机服务。浏览器可访问终端显示的地址，并复用运行中的桌面宿主；单独运行 `pnpm dev` 只启动页面，正式功能仍需宿主在线。当前仅运行开发模式，不安装或发布程序。

## 使用

- 添加工作区，在模型设置中配置可用连接，选择模型与思考等级后发送消息。
- 会话配置可选择工具和项目指令范围；MCP、Pi本地/npm/Git扩展与可选应用插件在设置中管理。来源登记、安装、启用和实际业务连接分别显示，npm/Git来源需要明确安装。
- “插件”统一管理文件工作栏、OpenCLI浏览器和远程访问，三者独立启停；短记录提供可独立导入的新接口示例。列表选择插件后，在详情编辑配置、查看影响范围或打开独立页面；来源导入按需打开，切换插件保留未保存的配置草稿。文件工作栏默认启用；OpenCLI和远程访问默认停用，按需要启用并完成各自连接。
- 文件插件通过会话右侧标签浏览目录与预览文件，明确交付文件和变更摘要位于所属轮次末尾。文件工作栏只读预览当前文件，保留同一会话中文件标签和阅读位置。手动编辑通过本机系统关联程序或已选择的外部编辑器完成；网页不直接保存文件。Git现状包含整个仓库的外部修改，会话操作页只展示原工具已确认成功的操作差异。
- 文件路径引用由Agent按需读取当前文件；源码、Markdown和PDF选区保留实际所选文字与位置，进入普通输入、发送和队列。原图片和工具patch沿原历史保留，不建立整文件历史版本库。
- OpenCLI使用官方全局 `@jackwener/opencli` 包和已有Chrome/Edge中的官方Browser Bridge。系统需有可用的Node.js/npm；插件页检测实际安装目录与版本，并提供安装、升级、卸载、启动和停止。全局后台与浏览器连接分别显示；升级、卸载、停止会影响其他OpenCLI使用者，卸载保留用户配置。已有后台启动时复用，版本不一致或连接失效须主动处理。会话无需手动绑定页面；Agent可使用网站命令和通用浏览器操作，Moon只提供命名会话与已配置浏览器环境。
- 远程访问通过evework的网页入口、扫码或连接链接接入正在运行的本机Moon。本机服务和远程插件需持续在线；公网手机需要可访问的HTTPS/WSS入口。连接链接具有本机控制能力，只交给需要接入的人；重置会使所有旧链接和连接失效。
- 运行中可停止、排队后续消息；结果未知时使用原操作核对入口，保留原稿与下一稿。
- 文本、文件路径和图片通过材料准备后交付。已有会话正文由 Pi 的本地 JSONL 历史保存。
- 模型请求和工具可能访问外部服务或修改工作区；连接检查可能产生模型费用。

Windows 安装时请选择用户目录之外、当前用户可写的位置，例如 `D:\Apps\Moon`。应用数据默认位于安装目录的 `data/`，包含会话、连接配置、材料、WebView 状态、日志和临时文件。开发模式使用项目内已忽略的 `.dev/moon/data/`；也可通过 `MOON_DATA_DIR` 指定开发数据根。

设置中的“数据与存储”可以查看或迁移数据目录。迁移会先保存并关闭相关资源，复制验证后启用新目录，保留旧副本；目标应是新的空目录。密钥、MCP 环境与请求头可能包含敏感信息，请将数据目录保留在当前用户的私人环境中。外部工作区文件和第三方程序自有数据仍由其各自管理。普通浏览器的用户配置由浏览器管理。

“关于与更新”从 GitHub 稳定 Release 检查版本，下载后校验发布签名，再由用户选择安装并重启。默认自动检查、手动下载；下载完成后退出应用需要重新下载。首次引入更新能力需手动安装新版本一次；开发模式不能安装正式更新。更新、重装和卸载均保留应用数据及外置数据目录。

## 开发资料与检查

- 插件规范：[plugin-spec.md](src/features/plugin-development/plugin-spec.md)。入口为“设置 → 开发工具 → 插件开发”或 `/devtools/plugin-development.html`，随正式版发布。
- `/project/`：模块职责、文件用途、源码和引用。
- `/ui-catalog/`：正式页面与组件的隔离演示、场景和规则。
- `/api-catalog/`：正式契约与主动调用调试；调试使用当前宿主。

后三项仅在 dev 提供。文件用途维护在 `devtools/project-purposes.json`，模块边界维护在 `devtools/project-modules.ts`，页面区域、场景和关联维护在相邻 `.catalog.tsx`；接口字段直接读取正式契约。

`pnpm contract:check` 检查契约与生成类型，`pnpm typecheck` 检查类型，`pnpm lint` 检查文件治理与代码，`pnpm build` 包含契约、类型检查及前端构建。新增顶层目录需在 `scripts/project-index.mjs` 登记职责；文件增删或重命名同步用途登记。静态无引用不能单独作为删除依据。

发行构建会静态解包并核对 NSIS 安装包，需要支持 NSIS 解码的完整 7-Zip CLI。默认查找 `C:\Program Files\7-Zip\7z.exe`，也可通过 `MOON_PACKAGING_7ZIP` 指向自有目录内的 `7z.exe`。这是 `desktop:build` 的发行验收前提，开发运行和前端构建不需要 7-Zip；当前仍只运行开发模式。

## 代码职责

- `src/`：正式React页面、共享组件、输入与读取状态；`src/lib/rpc/`共用本机和远程业务契约。
- `backend/`：本机Node服务、Pi会话、材料与原回执；`backend/plugins/`包含各应用插件自身的宿主、Pi与网页贡献，通用宿主只负责发现、权限和生命周期。
- `src-tauri/`：桌面启动、原生文件/目录选择、外部程序与本机进程所有权。
- `devtools/`：正式插件规范网页入口、开发检查页共用主题与分栏组件、项目结构页及文件用途登记；`ui-catalog/`：组件页面、正式演示及隔离服务；`api-catalog/`：接口页面、契约阅读和调试控制器；`scripts/`提供只读索引、共用治理规则、契约生成与构建打包。
- `.dev/`：Git忽略的开发数据、运行产物和过程记录。正式源码与用户工作区文件不在这里清理。

`AGENTS.md` 与 `DESIGN.md` 分别维护本地协作规则和界面规范，保持 Git 忽略；内部过程材料放在 `.dev/`。

插件前端公开类型位于 `src/features/plugins/plugin-api.ts`；`backend/plugins/example-note` 同时提供可从插件页导入的本地示例包。开发工具的插件规范页直接呈现这些正式定义与示例源码。

从“设置 → 插件”启用“MCP 服务”后，在详情打开“管理 MCP 服务”，设置固定端口、选择共享工具并复制 Codex/DSH 配置；独立 token 只在该页按需显示、复制或重置。OpenCLI 共享工具接收原生 argv，session 与标签页按实际安装版本的 OpenCLI 语法使用，profile 沿用插件配置。独立“日志”插件从详情进入查看 MCP 接入与对外工具调用；停用查看插件仍由宿主记录，日志存于当前数据目录的 `logs/`，按30天、10000条和8MiB先到限制保留。插件共享契约以正式插件规范为准。
