# Moon 插件开发规范

本文件是插件规范的唯一正文，由正式“开发工具 → 插件开发”页面直接读取。README、AGENTS.md 和 DESIGN.md 只引用本文，不复制维护插件协议。

## 范围与版本

Moon 是本地 agent 应用。插件运行扩展主要沿用 Pi；Moon 核心掌握页面结构，插件通过有限入口提供功能。

**本文是已确认的插件规范。Moon 前端接口版本为 1，运行扩展沿用 Pi 1.3.0。** 正式类型、包声明和接入示例见“接口与实现状态”。

- 规范确认日期：2026-10-17。
- 本次参考基线：Moon 安装的 Pi 1.3.0 及其对应官方文档；DSH 官方仓库当时的实现。DSH 的 master 链接会随上游更新，不表示未来版本自动成为 Moon 规范。
- 本文适用于内置插件和外部插件。默认随应用提供不等于核心，也不赋予额外界面权限。

开发者从本页查明允许的功能和位置，再阅读所用 Pi 版本及 Moon 正式接口；页面可在正式版离线阅读，外部参考链接需要网络。

## 核心与插件边界

按职责划分，不按是否默认内置划分。核心保证基础会话成立，插件扩展具体功能。

| 对象 | 归属与职责 |
| --- | --- |
| 启动、窗口、主导航、模型与凭据配置 | 核心 |
| 工作目录、会话创建、历史、分支和草稿 | 核心 |
| Agent 运行、停止、状态及宿主审批 | 核心接入 Pi |
| 输入框、用户附件、正文、工具记录和消息操作 | 核心 |
| 插件安装、启停、详情、注册接口和容器 | 核心 |
| 文件浏览、预览、交付展示、Git 差异、浏览器操作等 | 插件 |
| 工具、事件、命令、模型提供方、MCP 等运行扩展 | 插件通过 Pi 支持的契约注册 |

Pi 提供运行扩展能力，但不规定 Moon 的网页导航或布局。核心可在内部按模块组织，不因此把所有核心职责开放为第三方可替换区域。

**参考事实：** [Pi 1.3.0 扩展文档](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/extensions.md)列出了工具、事件、命令、会话数据及提供方等扩展能力。

## 允许的前端入口

只开放以下四类贡献。插件可以只提供其中一类，也可以完全没有前端。

| 贡献 | 位置与规则 |
| --- | --- |
| 工具 | 在会话配置中由核心统一展示和选择；插件提供工具定义。 |
| 独立插件页面 | 入口只在该插件详情内；核心负责打开、返回和页面容器。 |
| 会话右侧标签 | 插件提供入口和标签内容；核心决定打开、切换、关闭、宽度及会话归属。 |
| 轮次交付卡片 | 插件提供结果类型与卡片内容；核心放入所属轮次末尾的交付区域。 |

插件详情中的版本、来源、配置、启停和影响范围是核心管理界面，不构成新的业务入口。

不开放主导航、会话顶部、输入框工具栏或任意消息位置的自定义组件；不提供包裹整个会话页面的 `children` 接口。插件卡片不得接管消息列表，插件标签不得接管主区布局。

**参考事实与 Moon 差异：** DSH 使用父级声明的插槽与右侧标签注册，还支持更广泛的组合和覆盖。Moon 只采用“注册内容、宿主决定位置”的关系，不复制完整通用插槽框架。代价是插件只在上述位置表达功能。

来源：[DSH 插槽协议](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-slots/README.md)、[DSH 右侧栏](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-sidebar-right/README.md)。

## 结果展示与轮次

| 信息 | 展示位置 |
| --- | --- |
| 执行过程、参数、工具输出、失败和中断 | 对话流中对应的工具记录 |
| Agent 解释、总结、普通链接和图片 | 正常消息正文 |
| 明确交付的文件、报告等结构化结果 | 本轮收尾正文之后、消息操作区之前 |
| 文件预览、差异详情、浏览器操作 | 会话右侧标签 |
| 安装、连接与全局配置 | 插件详情或从详情打开的独立页面 |

“轮次”是一条用户请求引起的完整执行过程，包含中间多次模型调用和工具调用。不能把 Pi 的每次内部模型调用都当成用户轮次。

交付区位于轮次末尾；轮次中断时只保留已经明确形成的有效结果，不生成成功交付状态。普通工具输出不会自动成为交付卡片，插件必须明确提交交付数据。宿主不从任意文本中猜测成果。

参考：[DSH 交付展示](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-deliverables/README.md)。

## 文件列表归属

文件目录树、交付文件清单和变更文件清单归文件插件。用户添加到消息中的附件列表归核心。

| 对象 | 归属与位置 |
| --- | --- |
| 工作区目录树、文件列表 | 文件插件；会话右侧“文件”标签。 |
| 本轮交付文件清单 | 文件插件；轮次末尾交付卡片。 |
| 本轮变更文件清单、Git 差异 | 文件插件；末尾摘要，右侧查看详情。 |
| 文件预览、外部编辑器打开 | 文件插件；右侧标签，编辑器配置在插件详情。 |
| 用户输入附件列表 | 核心；输入区及发送后的用户消息。 |
| 会话工作目录、基础文件工具执行 | 核心与 Pi 运行层。 |

停用文件插件后，目录树、专用预览和专用卡片渲染停止；用户附件、基本对话及 Pi 基础文件工具继续工作。历史交付仍保留核心可读的名称、路径和摘要。

文件插件默认启用也不获得特殊布局权限，只通过右侧标签与末尾交付卡片呈现功能。

**参考事实：** DSH 文件树是注册到右侧栏的独立 UI 包，拥有自己的目录查询和展开状态。这支持文件内容与宿主容器分离，但不要求 Moon 复制其全部文件系统架构。[DSH 文件树](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-sidebar-files/README.md)。

## Pi 运行能力与界面适配

运行扩展遵循使用版本的 Pi 接口，包括工具、事件、上下文处理、命令、提供方及 MCP 等；不是把 Pi 的终端界面原样搬到网页。

| 能力 | Moon 的目标处理 |
| --- | --- |
| 工具、事件、上下文处理和命令等 | 按 Pi 接口运行，在详情列明影响。 |
| 命令调用 | 核心输入处理命令文本，不新增插件按钮或候选入口。 |
| `confirm`、`select`、`input`、`editor` | 核心统一呈现在该插件的右侧交互标签；无自定义前端的插件使用标准内容。 |
| 通知、状态、文本 widget | 收入对应插件右侧标签，不增加全局提示区或输入框周边区域。 |
| 终端自定义组件、页头和页脚等 | 不直接转换为 Web；需要界面时声明 Moon 前端贡献。 |

插件业务确认和 Moon 宿主审批保留各自身份。前端组件不能直接改写核心运行、停止或审批状态；运行扩展只能按 Pi 对应接口定义影响执行。

**兼容边界：** 不承诺任意 Pi 插件的终端 UI 原样兼容。Pi 本身也区分运行模式；RPC 支持部分交互请求，不能承载完整终端组件。[Pi RPC UI 文档](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/rpc-extension-ui.md)。

## 包结构与接入路径

一个插件包包含元信息、可选 Pi 入口、可选 Moon 前端入口与影响声明。工具、页面、标签和卡片均为可选贡献，不要求为无界面插件编写前端。

| 约定 | 目标行为 |
| --- | --- |
| 包来源 | 支持本地、npm、Git 来源；沿用 Pi 的运行资源组织。 |
| 前端资源 | 外部插件发布预构建前端资源，由宿主加载，不修改或重新编译 Moon。 |
| 共享依赖 | 前端复用宿主 React、公共组件及主题。 |
| 注册 | 独立页面、右侧标签、交付卡分别注册并记录所属插件；贡献 ID 冲突明确报错。 |
| 接口版本 | 发布包注明适用接口版本，宿主识别不兼容状态。 |

接入时先判断是否只需要 Pi 运行扩展；需要界面时，再选择允许的贡献位置。配置归插件详情，会话操作归右侧，交付摘要归轮次末尾。

**正式接入：** 带 Moon 界面的外部包在 package.json 的 `moon` 字段声明接口版本、入口和贡献；前端发布为预构建的单文件 ES 模块，默认导出接收宿主 SDK 的工厂。模块通过 SDK 使用宿主 React 和公共组件，不在 bundle 中重复包含 React。静态资源通过 `sdk.resource(path)` 获取，停用时由宿主释放资源 URL。

参考：[Pi 1.3.0 包文档](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/packages.md)、[DSH 前端模块加载](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/modules/README.md)。

## 布局约束与生命周期

插件前端与宿主在同一页面运行，以 React 组件接入。核心管理容器的位置、尺寸、排序、打开与关闭；插件负责容器内部内容。

| 规则 | 具体要求 |
| --- | --- |
| 样式与访问 | 使用局部样式、共享主题和公开接口；禁止修改宿主 DOM、覆盖全局样式或依赖未公开内部实现。 |
| 加载失败 | 保留明确的插件错误状态和已打开标签，允许重新加载恢复；首次加载失败也在会话插件入口页提供错误及重试。组件渲染错误由所属边界呈现，插件代次更新后重新挂载标签和交付组件。只有确认停用、移除或贡献已删除时才移除对应标签。 |
| 停用清理 | 移除入口和组件，释放所属订阅、监听及后台资源。 |
| 会话切换 | 内容与会话身份绑定，异步结果不能写入其他会话。 |
| 运行期间启停或升级 | 不在正在执行的轮次中替换扩展代码；在空闲边界重建受影响实例并说明生效状态。 |

前端 SDK 和会话 context 的操作调用固定创建该界面时的插件代次；实例变化后旧界面调用会被拒绝，重新加载后才能操作。应用操作在授权前固定实例和代次，取得执行租约后再次核对；旧实例的待执行操作不得转交新实例。配置、操作参数、操作结果和共享工具参数均按声明的字段类型严格校验，不隐式转换字符串、数字或布尔值。命令使用本次调用客户端的上下文及界面目标。

外部应用入口和 Pi 入口共用执行来源记录。已在当前进程执行过的 JavaScript 来源发生更新后，必须重启 Moon 才能启用新代码；重新导入相同来源不绕过此要求。

不引入 iframe、另一套隔离系统或配套跨框架通信。这里是协议、布局和生命周期约束，不是阻止同页面代码操作 DOM 的安全沙箱。

**参考事实：** DSH 通用插件前端链路加载脚本并在宿主 React 树中渲染注册组件。Moon 借鉴这条关系，不照搬 DSH 完整动态模块与布局系统。

来源：[DSH 加载实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/modules/src/client/system.ts)、[DSH 渲染实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-renderer/src/client/scoped-slots.tsx)。

## 配置、历史与降级

| 对象 | 规则 |
| --- | --- |
| 插件配置 | 按插件保存；插件拥有自己的业务字段。 |
| 会话内状态 | 绑定会话；与历史有关的数据按当前分支恢复。 |
| 交付记录 | 保存插件来源、结果类型、数据版本、展示数据、文本摘要与所属轮次。 |
| 插件缺失、停用或结果不兼容 | 核心显示保存的摘要，不执行插件重新生成历史结果。 |
| 文件内容 | 交付保存文件引用，不默认复制全部内容或建立文件版本仓库。 |

文件引用不保证原文件永远存在或内容不变。预览读取当前可访问的文件，文件消失时明确反馈，不伪装成历史内容快照。

**参考事实：** Pi 区分跟随分支的工具结果数据、非模型上下文持久数据和会话外存储。交付记录字段见下方正式接口。[Pi 状态规则](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/extensions.md#state)。

## 影响范围与启停语义

插件详情必须让用户看懂插件做什么、会出现在哪里，以及何时生效。

| 展示内容 | 数据依据 |
| --- | --- |
| 工具、命令、运行钩子及其他注册能力 | 宿主实际发现的注册项。 |
| 页面、右侧标签和交付卡片 | 该插件声明并实际注册的贡献。 |
| 文件、浏览器、网络、进程等外部影响 | 作者声明，明确与实际注册信息区分。 |
| 安装、启用、运行状态与业务连接 | 各自真实状态，不混为一个“可用”。 |

未声明不能显示为“没有影响”。取消选择某个工具，不等于停用插件的事件钩子；工具是否可调用遵循 Pi 对应工具暴露方式和 Moon 正式配置契约。

## 对外共享工具与 MCP

应用入口 `activate(host)` 可选返回 `sharedTools`；正式类型直接列在下方。它独立于 Pi 聊天工具工厂，不捕获某场聊天的工具实例，也不要求先创建聊天或运行模型。宿主按 `<plugin-id>__<name>` 提供带归属的稳定名称、描述、严格对象参数 schema，以及标准文本、图片和可选结构化结果。

只有作者明确声明 `shareable: true`、插件当前启用且用户在 MCP 服务页选择共享，工具才可列出和调用。宿主在调用时再次检查授权和代次，严格校验参数及结果，持有原插件 lease，并传递取消信号；插件应等待后端工作实际结束后再结算取消或关闭。工具不得依赖某场 Moon 聊天的审批或专用 UI；客户端负责自己的逐次审批。工具描述及 annotations 必须如实说明写入影响。

MCP 服务是可启停的内置插件，使用官方服务端 SDK 2.3.1 和 Node 适配 2.1.1：统一 `/mcp` 地址，仅监听 `127.0.0.1` 固定可配置端口，校验 Host、Origin 与独立 bearer token。现代协议由 SDK handler 处理；2025 协议沿 SDK 原生 Streamable HTTP 协议会话处理初始化、取消和工具清单变更通知。协议连接仅服务 MCP，不映射 Moon 聊天或浏览器 session。客户端未刷新工具目录时重新连接；缓存旧名称的调用仍会重新授权。

`OpenCLI` 首版共享 `opencli__run`，参数为 `arguments` 原生 argv 数组，按 OpenCLI 2.0 接口执行。外部浏览器调用使用 `browser <command> --session <name>` 和原生 `--tab`；Moon 要求已安装程序提供 `--session` 和 `--profile`，不提供旧版位置参数兼容。Moon 不注入或覆盖外部 session，不增加 context_id 或任务会话 API，不因 MCP 断连或插件停用关闭外部已有页面。Moon 内部 Pi 工具继续自动注入其原生 `--session`；只有这些 Moon 创建的 session 进入自身清理清单。两条入口共用执行与截图转换，仅从 `{ ok: true, data: "…" }` 读取截图 base64，保存路径回执仍作为文本返回，图片保留原有大小上限。profile 遵从插件配置，全局管理仍在详情。

日志写入属于宿主共享调用和 MCP 接入边界，独立日志插件只负责查询。记录开始、成功、失败、拒绝、取消、耗时及服务事件；默认只记录字段名/类型/长度，插件可提供明确安全的有界摘要。截断不是通用脱敏保证；不得记录 token、密码、图片 base64、type 文本、eval 脚本、完整 URL、页面正文或原始 stderr。原始业务错误可返回授权调用者，但日志只保存安全类别说明。客户端名为自报、不是认证身份；缺少或格式不允许时显示“未提供”。日志在应用数据 `logs/` 保留30天，最多10000条和8MiB先到为准；落盘故障在服务及日志页明确显示，退出等待必要写入，不覆盖原工具错误。

MCP 服务及日志独立页面只能从各自插件详情打开。

## 接口与实现状态

正式接口集中在以下源码。产品页面直接嵌入公开类型和真实示例，避免复制维护第二份定义。

| 内容 | 正式实现 |
| --- | --- |
| Moon Web API 1 | `src/features/plugins/plugin-api.ts`：页面、标签、交付卡与上下文类型。 |
| 前端注册与资源加载 | `src/features/plugins/plugin-web.ts`：校验贡献、加载独立 ES 模块、释放插件资源。 |
| 宿主容器 | `src/features/plugins/plugin-workspace.tsx`：会话右栏与轮次交付容器；仅宿主接收会话 children。 |
| RPC 与资源 | `backend/plugin-contract.mjs`：管理、业务操作和 `pluginResource` 资源读取。 |
| 运行加载与注册汇总 | `backend/plugin-host.mjs`：原生 Pi 接入、插件归属、影响信息和代次。 |
| 独立安装示例 | `backend/plugins/example-note`：package.json、Pi 工具与预构建前端，和内置形式使用同一工厂。 |

外部包的 `moon` 字段支持：`apiVersion: 1`、可选 `pi`、`app`、`web` 入口、`configurationSchema`、`defaultConfiguration`、`effects` 和 `contributions`。入口均相对包根目录。仅有 Pi 资源的包不需要 moon 字段；需要配置或应用操作的 Pi 入口通过 moon.pi 声明，接收 `{ configuration, application, context, scope }`。

前端工厂返回 `PluginWebModule`，身份必须使用 `sdk.pluginId`。页面、标签和交付类型必须与清单的 kind/id/version 匹配；不允许重复注册。`connectSession` 只用于无界面的会话订阅，返回同步清理函数，所有异步任务必须响应 signal。

- 独立页面：`pages`，入口来自插件详情。
- 会话标签：`tabs`，kind 为 `session-tab`，通过自己的 `context.openTab(id, payload)` 请求打开。重复打开保留原位置，未传 payload 时保留已有参数。`context.closeTab(id?, resource?)` 只能关闭本插件的标签；省略 id 时关闭当前组件所属标签实例；无所属标签时仅能关闭本插件当前选中的标签。相同标签类型的多资源实例可用 resource 指定，目标有歧义时不关闭。关闭不等于收起宿主面板；收起与标签切换保留已挂载内容，关闭或停用才释放标签资源和 signal。`pi-interaction` 是宿主标准交互保留标识，插件不得注册同名业务标签。
- 资源标签仍使用 `tabs` 注册：可提供 `resourceKey(payload)` 定义资源身份，提供 `title(resource)` 定义标题。此类标签从插件内容或交付卡打开，不在入口页重复展示空预览入口；宿主按插件、标签类型与资源标识去重并恢复，正文通过 `context.resource` 读取已保存身份。`icon`、`description` 仅用于既有右栏入口，不产生新位置。目录、文件预览和变更使用同一宿主标签栏，插件内容不再重复管理第二套文件标签。
- 轮次交付：`deliveries`，kind 为 `delivery`。同轮、同插件、同类型的数据由核心分组，组件接收 delivery 和 deliveries。
- 工具显式交付：返回 `details.moonDelivery = { kind, version, payload, summary }`。payload 是 JSON 字符串，最多 64KiB；summary 是可读摘要，最多 16000 字符。宿主补充插件身份与来源，在 Pi 历史中保留，并在投影中关联真实工具位置与用户轮次。
- 使用 Pi tool_result 钩子形成明确交付时，保留原工具内容及已有 details。失败工具不形成成功交付。

OpenCLI 不提供手动绑定、解绑或目标状态栏。它接入网站命令和通用浏览器操作，按会话提供命名会话，浏览器环境在插件详情配置。普通网站命令和能力发现不以前台页面绑定为前提。

旧 API 1 短记录示例已迁入统一插件目录，保留原工具名和既有配置；旧扩展目录不再作为新插件接入方式。历史交付读取原保存数据，不加载旧组件或重新执行业务。旧版预览请求及普通自定义工具结果继续通过核心工具记录阅读，不推断成新的明确交付。
